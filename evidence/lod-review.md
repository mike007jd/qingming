# LOD 实测与画面对照

默认已启用自动 LOD，近景使用原模型。场景设置 → 画质 → 全程完整 · 对照，可立即关闭 LOD。

Apple M2 Max / ANGLE Metal，1280 × 720，同一冻结时间、同一镜头，预热后交替测量八次，每次用 GPU readPixels 等待整帧完成，取中位数：

| 镜头 | 全程完整 | 自动 LOD | 帧耗时降低 | 全通道三角形减少 |
|---|---:|---:|---:|---:|
| 全景 | 159.7 ms | 132.4 ms | 17.1% | 60.8% |
| 桥下 | 118.1 ms | 96.4 ms | 18.4% | 58.9% |
| 人物 | 84.1 ms | 68.6 ms | 18.4% | 40.6% |

这是相对于上一轮渲染优化后的进一步改善。LOD 将实例分配到多档网格，draw calls 会增加；实际总帧耗时仍下降。帧率与收益随分辨率、视角、硬件和后台负载变化，表格使用帧耗时而不是瞬时 FPS。

建筑、人物复用现有三档网格。新增的 345 个细节原型覆盖 2088 个网格实例，独立 LOD GLB 为 53.6 MB，使用原贴图和材质。树叶保留每片外轮廓及数量，只简化叶面内部折线；新增模型保留 UV、顶点色与同一风动/画卷入口。人物各档同时应用终稿脸手比例和衣服修整，最高档顶点字节及原始索引经比较保持一致。桥梁、船舶和水面几何保持完整。

选择依据是实际输出像素，含镜头缩放、包围球深度与导出尺寸；20% 返回滞回避免边界反复切换。主视图和倒影视图独立选择与记忆档位，阴影还依据阴影纹理像素密度保留较高精度。颜色、法线和深度通道使用同一选定模型。Three.js 原生 LOD 也提供[滞回机制](https://threejs.org/docs/pages/LOD.html)，这里将同样机制接入现有实例批次，并计入输出像素。

贴图、水场 2048 × 256、完整水面网格、4096² 阴影、逐帧全分辨率反射/折射与 4× MSAA 未降低。

## 验证与界限

- [720p 性能原始数据](lod-720p.json)：三个镜头，每侧八帧。
- [4K 对照原始数据](lod-4k.json)：十景 × 淡彩/古绢/关闭画卷，30/30 通过可见实例、三角形、所选几何与 GPU 检查；人工检查下面三组近远景。4K 每侧仅两帧，用于画面检查，不据此宣传性能。
- [最终 GPU 与交互检查](lod-gpu-verification.json)：42/42，通过步行过桥、门体/碰撞一致、代表性商铺和院落进出、船体采样、尾波和三种画卷十景。
- [完整模式原有回归](lod-full-mode-regression.json)：三个镜头的法线、阴影、倒影与折射缓冲保持逐值一致，水场完整数据一致。
- npm test：桥、门、生态、变形一致性，以及 LOD 唯一选档、拉近恢复、缩放、4K、滞回、倒影独立档位与关闭对照。
- npm run test:package：四份 GLB、四份原生 Blender、本地贴图与资源、LOD 来源/通道/三角形检查通过。

LOD 会改变远处的细节像素，不是逐像素无损替换。4K 三十组整体 RGBA RMSE 最大 1.608 / 255；近景人物淡彩镜头为 0.0079 / 255。这些数值与静帧供对照，不能代替所有自由相机路径的视觉判断。最高精度模型始终保留，精细审图可切换“全程完整”。
