# 同画质性能优化验证

本机 Apple M2 Max / ANGLE Metal / Three.js r179，1280 × 720，固定镜头和模拟时间，每侧 8 个计时帧，交替执行前后路径。计时包含 GPU 完成整帧所需的同步等待，排除首次编译；下列数值是中位数，不是所有设备或漫游位置的帧率承诺。

| 镜头 | 优化前 | 优化后 | 帧耗时下降 | 全通道绘制次数 |
|---|---:|---:|---:|---:|
| 全景 | 197.6 ms | 163.3 ms | 17.4% | 11720 → 9858 |
| 桥下 | 159.8 ms | 122.8 ms | 23.2% | 8731 → 7068 |
| 人物近景 | 117.2 ms | 83.1 ms | 29.1% | 6895 → 5446 |

水场的同一段 2 秒输入，两侧都执行 240 个物理子步。求解和读回耗时 19.1 → 15.2 ms，下降 20.4%；绘制次数 480 → 300。高度、速度、泡沫、泥沙的全部浮点值完全一致，非有限值检查通过。

## 保留的画质

3 份 GLB 的 SHA-256 与原交付清单完全匹配，34 份本地贴图及 3 份 Blender 源文件完整。模型和纹理没有修改；仍使用完整网格、4× MSAA、4096² 阴影、与最终画面同分辨率的反射/折射、2048 × 256 水场和 395457 个水面顶点。画卷 shader、采样精度、物理步长、骨骼和风动均保留。

三种画风 × 十个固定镜头，共 30 组真实 3840 × 2160 对照全部通过。主视图三角形数量一致，法线、阴影、反射、折射四种缓冲全部逐值一致。最终 4× MSAA 颜色输出本身存在未修改基线也能复现的极少量重复帧差异；测试先测量基线自身，再要求优化后的差异保持在该范围附近，没有宣称所有最终像素完全相等。4K 对照最高 RMSE 为 0.04355 / 255。

## 实际改动

- 阴影独立生成，移除随阴影绘制后被丢弃的整城颜色通道；阴影实例按光源视锥保守裁剪，保留镜头外遮挡物及活动部件边界。
- 场景世界矩阵每帧更新一次；折射结束后直接复用主镜头的实例缓冲；跳过未被读取的最终深度拷贝。
- 同一次水场更新仅生成一次相同扰动输入，继续执行每一个 1/120 秒物理子步。
- 修复 r179 在阴影后的倒影通道可能复用旧实例上传缓存的问题。原始与优化计时路径共同使用这项修复，因此比较的是相同、正确的倒影内容。

## 复现

从本目录双击 START.command。

- /?perf=1：三个镜头的交替性能对照和全水场回归。
- /?perf=1&full=1：三种画风 × 十景的 4K 对照；每侧一个计时帧仅作附带记录，性能结论使用上面的 8 帧交替基准。
- /?verify=1：尾波、交汇、转弯、靠岸、桨点、暂停、通行、门体与三种画风检查。
- npm test：桥面、门体、布局、生态、变形以及镜头外阴影遮挡物回归。
- npm run test:package：资产和启动目录完整性。

动态场景验收 42 项全部通过，详见 [本次 GPU 与交互检查](performance-gpu-verification.json)。浏览器检查无 JS、GLSL 或 WebGL 错误。

原始数据：[720p](performance-720p.json)、[4K](performance-4k.json)。所有优化代码均在 Qingming_Final 内，两份原工程及原 shader 原件保留。
